# doc/plan/code-size-budget —— 代码体量预算：前端组件 ≤ 500 行（C64）

> 池子行原文照搬（2026-11-18 用户定）：
> **前端组件不能超过 500 行，超过 500 行必须要拆分。**

**定位**：长期项。不是一次性重构，是**给"文件会长胖"装一个判据** —— 所以它的重点不是"把 `page.tsx` 拆了"，而是"以后不许再长回来"。

---

## 一、需求（人话）

组件太长了读不动：一个文件里塞着状态、副作用、十几个 handler 和四块 JSX，改任何一处都要先翻 700 行。用户定的红线是 **500 行**。

**AGENTS.md 第 11.9 条已经有这条原则**（「页面超过 500 行 → 拆组件」），而且写得比"500"细：

- 500 是**触发线不是目标**：不到 500 行但"一个文件里两件事"就该拆
- 超过 500 行但逻辑单一（如一个长 switch）可以留
- 怎么切：按「**能一句话说清它负责什么**」

⇒ 本项要补的是**机器判据**（跑一下就报），不是重新发明原则。

## 三、详细设计（判据与脚本）

| 项 | 定案 |
|---|---|

| 阈值 | **500**（用户定，不讨论） |
| 范围 | `app/**/*.tsx` —— **包括 `page.tsx` 这类路由文件**（它就是典型违规者） |

## 四、拆分路线（`app/page.tsx` 的四刀，按"能一句话说清"切）

现在 `Home()` 本体约 560 行（76–636），后面还挂着 6 个模块级纯函数（637–722）。

| # | 拆出 | 一句话职责 | 估计移走 |
|---|---|---|---|
| 1 | `app/components/composer/` | 输入台：卡 + textarea + 工具栏 + 状态条 + 空态工作空间行 + 命令面板接线 | ~180 行（含 `composerPlaceholder`） |
| 2 | `app/components/empty-hero/` | 新会话空态的品牌与提示（现在是模块级 `emptyHero()`） | ~30 行 |
| 3 | `app/components/session-head/` | 右栏第一行：标题 + 模型名 + 「对话/轨迹」tab | ~60 行 |
| 4 | 剩下的 `Home` | 状态与编排：session / runs / traces 三条线 | —— |

**四条硬约束**：

1. **输入框不许重挂**（C57 的 4.13 第 1 条）：`Composer` 在 `Home` 里是**稳定子节点**，空态 ↔ 会话态只换 props / `data-*`，不换组件身份。
2. **拆出来的组件通过 props 收数据、不读全局 store**（§10.9 第 4 条）。若某个组件要读三个以上的 store，说明切口选错了。
3. **一行逻辑不搬家**：这一批是**纯搬迁**，不改行为。撞到需要改逻辑的地方，单独开一行池子，别混进来。
4. **拆完仍超 500**：第 5 刀是 `app/lib/use-session-actions`（新建 / 重命名 / 删除 / 选择这一组互相牵动的 handler）。⚠️ 但要先判断它是不是**纯计算** —— 不含 React 状态与副作用的东西**不许包成 hook**，该进 `app/lib/`（§11.9 的核心分界）。

**顺序**：先 2（最小、最独立）→ 3 → 1（最大，但约束最硬）→ 再量一次，决定要不要第 5 刀。每步 `tsc` 绿再下一步。

### 8.3 拆的时候真撞上的四个坑（都是下一个拆的人会再撞的）

1. **CSS Modules 让"跨文件的类名"根本指不到。** `page.module.css` 原来有

2. **"谁在栅格里哪一行"必须留在页面。** `.stage` 的行模板、`.composerArea` / `.decisionHost` 的 `align-self`

   页面的 `data-empty` 规则没东西可选中了。判据一句话：**这条规则是在管"它在页面上的位置"还是"它自己长什么样"**。
3. **布局 effect 的依赖要换对。** 吸底滚动的 effect 原来盯 `[messages, follow]`；搬进 `TranscriptPane` 之后它拿到的是
   折好的 `turns`（`buildTranscript(messages)` 的产物，`useMemo` 缓存）。**引用变了就等于"有新内容"**，
   所以依赖改成 `[turns, follow]` 是等价的 —— 但这一条要能说出"为什么等价"，不然就是搬错了还看不出来。
4. **死 CSS 会被搬走而不被发现。** `.modeBar`（审批模式切换条）在 C57 把档位搬进输入台卡片之后就没人用了，

#### 8.6.1 跨文件选择器：同一条坑，第二次撞

旧 CSS 里有这条，它**横跨两个组件**：

```css
.turn:hover .answerActs { opacity: 1; pointer-events: auto; }
```

`.turn` 留在 `index`，`.answerActs` 搬进 `answer-actions`，两个类名各自被哈希 ⇒ 规则静默失效。
**表现是"悬停回合、复制按钮再也不出现"，控制台一个字都不报**（`opacity: 0` 还在，只是没人把它翻回来）。

解法与 8.3 ① 同一条：**跨组件边界用属性选择器**。
`<div className={styles.answerActs} data-role="answer-actions">` + `.turn:hover [data-role="answer-actions"]`，
weight（权重）不变，仍是三个 class 级。

⇒ **这条现在可以当结论用了**：拆 CSS 时，凡选择器里出现"两个不同组件的类名"，就必须先把其中一个换成
`data-*` 钩子，否则失败是静默的。两次撞的都是它，所以写进这里。

#### 8.6.2 顺手逮到的存量缺陷：两处悬空样式引用

`tool-row` 里 `className={styles.stepBlock}` / `styles.kv` 两个类，**从 C57 起就不存在**
（`git show HEAD:` 里查过，旧 CSS 从来没有这两个类）⇒ 一直解析成 `undefined`，等于没加类。

- 处理：删掉这两处 `className`（**零视觉变化**，DOM 一个字节都不变），并把 CSS 头注释里那句"故意没有"删掉。
- 顺带把这类检查做成一次扫描：**全仓库 `.tsx` 里 `styles.X` 引用了但对应 `*.module.css` 里没有定义的，现在 0 处**。
  做法 = 解析每个文件的 `import <alias> from "*.module.css"` → 收集 `<alias>.Class` 引用 → 与该 CSS 的选择器集合求差。
  **以后拆分前先跑一遍，比人眼靠谱。**

⚠️ **诚实记一笔**：这次清理和搬迁混进了同一个 commit。判据是"**它是不是零行为变化**" ——
删掉一个恒为 `undefined` 的 className 不改 DOM，且 commit message 明写了；若它会改行为，就必须单独一个 commit。

## 九、改判（2026-11-20）：判据从「自建脚本」改成「ESLint 内置规则」

用户原话：

> 「**不可以直接写到eslint里面吗 这样超过500就报错了 都不能提交代码了**」

§三 的落点写的是 `scripts/check-size.mjs`（自建脚本 + 手动跑）。这一节把它整个换掉 —— 脚本**不建了**。

### 9.1 落点

`eslint.config.mjs` 里加一个作用块（约 20 行，含注释）：

```js
{
  files: ["app/**/*.tsx"],
  ignores: ["**/*.test.tsx"],
  rules: { "max-lines": ["error", { max: 500 }] },
}
```

`max-lines` 是 ESLint **内置**规则（本项目 9.39.5），默认**连注释和空行一起数**，正好等于本文件 §二 的口径。

### 9.2 为什么它比自建脚本好（四条，前三条是用户点出来的）

1. **提交门早就存在**：`husky` → `lint-staged`（`*.{ts,tsx}` → `eslint --fix`）⇒ 规则一加就**真的挡提交**。
2. **`max-lines` 不可自动修复** ⇒ `eslint --fix` **不会把它悄悄放过**（能修 = 等于没拦，这条最容易被忽略）。
3. **编辑器里当场变红**，不用等到提交。
4. **少一个"要记得跑"的命令** —— 而"记不住"恰恰是这条规矩当初失效的原因（408 → 722 长回去、拆完当天又 541）。

### 9.3 实测（2026-11-20，真库上）

| 对象 | 结果 |
|---|---|
| 临时造的 501 行 `app/**/*.tsx` | `error File has too many lines (501). Maximum allowed is 500`，exit 1 |
| 临时造的 500 行 | 通过，exit 0（边界正好） |
| `app/page.tsx`（现况） | 通过 —— ESLint 数它是 **497** |
| 全库 `eslint .` | exit 0 |
| `--print-config app/page.tsx` | `max-lines: [2, {"max":500}]`（确实生效） |
| `path::String` 在测试文件上 | 未设置（`ignores` 生效） |

### 9.4 三条边界（写下来，免得以后有人以为"已经万无一失"）

1. **口径差 1 行**：ESLint 数的是"文件行数"，**末尾换行不算一行** ⇒ 比 `split("\n").length` 少 1。
   实测：`page.tsx` 是 **497**（物理行 498）。**以后一律以 ESLint 报的数字为准**，阈值 500 不变。
2. **拦的是"提交"，不是"进仓库"**：`git merge` 的合并提交**不跑 pre-commit 钩子**，`--no-verify` 也能绕。
   ⇒ **收尾仍要跑一次 `pnpm lint`**（这条本来就在 AGENTS 11.5 的收尾清单里，现在它有了真正的用处）。
3. **范围只到 `app/**/*.tsx`**：`.module.css` 与 `app/lib/**` 不管（同 §三 的"一次只上一把尺"）。

### 9.5 豁免姿势

真要留一个超长的"单职责"文件（典型是一个长查表 `switch`）：

```ts
/* eslint-disable-next-line max-lines -- 一个查表函数摊成 4 个只会让读的人多跳 4 处 */
```

**想豁免就得写一行理由** —— 与 C45 对那 4 处查表函数的处理同款，是故意的。

### 9.6 代价

原脚本能打印「**最大 498（app/page.tsx）**」这种**趋势读数**（有读数才看得出它有没有在长胖）；ESLint 不打印最大值。
⇒ 这个数以后只能住文档：§8.1 / §8.6.4 的表格就是它的存档。**下次想知道水位，翻这里或临时跑一句 `node -e`。**

### 9.7 我当初为什么写"自建脚本"（自省，别让这个坑重复）

用户看到这一版时的原话是「**我还在想你为啥要写个脚本**」。老实复盘：

1. **工具族的一致性被我当成了理由**：`scripts/check-plan.mjs`、`check-feedback-tokens.mjs` 都在那儿，
   于是"再来一个"看起来天经地义 —— 但"同族"不是需求，**"能被现有的门拦住"才是**。
2. **§六 第 3 条还专门拍板「暂不进钩子，先手动，被咬一次再升级」** —— 我是在替一个**从没发生过的误报**做保守设计，
   却忽略了一个**已经发生过的失效**（文件长到 722）。把"防回归的判据"做成"要记得跑"的东西，等于没有判据。
3. **根子上的错：没有先盘点"已有的门"。** ESLint 早在 2026-09-22（C45）就接好了，
   `max-lines` 是它的内置规则 —— 我是在一扇**已经装好的门**上，另起了一道**需要人记得去锁的栅栏**。

⇒ **沉淀成判据（下次设计任何"判据/检查"时先问这句）**：

> **判据先找已有的门**：lint → tsc → 单测 → 提交钩子 → CI，按这个顺序找；
> 全都挂不上，才自建工具。**自建工具的隐藏成本不是"写 40 行"，是它会成为又一个"要记得"。**
