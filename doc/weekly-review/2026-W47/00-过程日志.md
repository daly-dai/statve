### 二、那个 bug 值得单独记（"跑完不收起"）

**症状**（用户 11-18 报）：命令跑完了，过程组还摊着；**刷新页面**才折起来。

**根因**：`const [open, setOpen] = useState(!collapsedByDefault)`。`useState` 的初值**只在挂载时算一次**，而这一轮是**边跑边长**的 —— 挂载那一刻还没回答，初值算出 `false`（展开）；跑完之后判据翻成 `true`，**可 state 不会再读一次初值** ⇒ 永远停在展开。

**修法**：把"展开"从 state 改成**派生值** —— `const [manual, setManual] = useState<boolean | null>(null); const open = manual ?? !collapsedByDefault;`。用户点过就以他为准，没点过就跟着判据走。判据本身抽成 `app/lib/transcript` 的纯函数 `shouldCollapseProcess(turn, live)` + 4 条单测。

**教训**：**"默认值"和"初值"是两件不同的事**。默认值可以随状态变，初值不能。凡是想用 `useState(!某派生态)` 表达"默认展开/默认折叠"，都要问一句「这个派生态以后会变吗」。

### 七·补：当天晚些时候补的「用时」（第二批，未提交）

C57 标了已交付，但 4.5 与 5.3③ 写的「用时」没落地（代码里只有步数）。用户发现后定「补，放在 AI 会话顶部那行文案后面」。

**先纠一个我自己的错**：我 18 号上午说过「用时做不了，assistant 时间戳是发送时刻、不可靠」。查了源码，**这句话是错的** —— `timestamp: Date.now()` 写在**流读完、装配最终消息**那一步（`lib/deepseekModel/index.ts:386/523`），而且它**落盘**了（会话 JSONL 里 23 条消息、缺时间的 0 条）。所以「历史回合也能算用时」，4.11 那条代价整个作废。

**算法**：回合内「最早」与「最晚」消息时间戳之差（min/max，防顺序不单调）。⚠️ 一轮里**有多次模型调用**，取某一条 assistant 会少算一大截 —— 实测那一轮整轮 118.8 秒，单看最后一次调用只有几秒。

**形态**（用户 18 号拍板，两轮）：位置是**甲 侧栏会话行**（时间槽换成计时器）+ **丙 过程组头**；乙（输入台）丁（状态条）不做；超一小时不变色。
格式我先分成了两种 —— 跑着 `3:16`、跑完 `1 分 59 秒`，理由是"一个是钟、一个是回执"。**用户当场否了**：同一个数在一屏里两种写法就是乱的。统一到 **`formatElapsed` 一个函数**（`3:16` / 过小时 `1:02:15`），理由见代码注释：侧栏那槽是定宽的、等宽数字不抖、一件事只有一处定义。代价写在详案里：`0:00` 不如「不到 1 秒」有人情味。

**两条被机器拦下来的教训**（同一个 hook 连撞两次，都是我没想起来）：
1. `useElapsed` 第一版渲染期 `Date.now()` → `react-hooks/purity` 报「Cannot call impure function during render」。**渲染必须幂等，读时钟就不是。**
2. 改成 state 之后在 effect 里直接 `setNow(Date.now())` → `react-hooks/set-state-in-effect` 报「Avoid calling setState() directly within an effect」。最后把"订阅时先给一次当前值"挪进 `subscribe()` 里。

**一个设计上的意外收获**：侧栏的「在跑」我一开始只认 `running`，实测发现**卡在审批框里那只会话不显示计时器** —— 而那恰恰是最容易一放半小时的状态。改成 `LIVE_PHASES`（running / waiting-approval / waiting-ask）三种都算：点负责区分状态，计时器只回答"过去多久了"。

**读数**：真机上侧栏走针 `0:04→0:15`、过程组头 `正在执行 bash… · 0:04→0:12`；跑完的头 `读了 17 个文件 · 搜了 1 次 · 16 秒`；0 步的回合 `不到 1 秒 + 0 步`。静态四件套全 0，单测 **875 / 62 文件**。

⚠️ **两条没验到的**：① 缺 timestamp 的显示路径（真实数据里没有这种消息，按夹具规则不造）② 侧栏在 `waiting-approval` 下走针（机制同 running，但要等 60 秒审批超时才看得到，留给用户顺手看）。
