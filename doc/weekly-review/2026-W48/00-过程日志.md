## 11-24 ~ 11-27 · B10 调查沉淀 + C68 缓存命中量可见 —— 3 个 commit

### 一、这一批到底做了什么

**B10 的调查沉淀**（`0c153ba`，分支 `feat/b10-workspace-memory`）：把 pi / codex / opencode / DSH 四家「工作区记忆怎么注入」读成一份一手对照（每家带 `file:line`），压成三个变量（内容放哪 / 何时读文件 / 超长怎么裁），并记下池子行那句「`systemPrompt` 常量 → 工厂」**已经过期**。

**C68 缓存命中量可见**（`adaacf4` 文档 + 本条代码 commit）：把 provider 回包里本来就有的缓存命中数（`prompt_cache_hit_tokens` / `prompt_tokens_details.cached_tokens`）读进 `Usage.cachedInput`，界面上给两处：
① 圆环**右侧常驻百分比**（不点开就能看到上下文占用）；
② 面板里**四行缓存账**（本轮调用 N 笔 / 累计输入 / 命中缓存 / 命中率）。

### 二、关键决策（含为什么）

1. **口径：取最后一笔 → 累计**（11-27 改判）。第一版按"最后一笔 ≈ 这一轮总账"写，用真实会话一量发现**差 8 倍**（最后一笔 25,238，13 笔累加 201,343）——一轮里模型被调 13 次，每次都重读完整历史。这条是用户追问"中间步骤没有用量吗"引出来的，问得对。
2. **停止态：不是"无用量"，是"最后一笔未计入"**。usage 只在**流的最后一个 chunk** 回，中止 = 那个 chunk 永远不来；但同一轮前面完成的每一笔、以及之前所有轮次都完整落盘。所以面板分三态（正常 / 已停止但有钱 / 已停止且一笔都没完成）。
3. **位置：只做圆环面板（B）**，不做回合尾读数（A）、不做轨迹逐笔（C）。判据：默认不打扰，点开才看。
4. **B10 走"系统提示词"还是"会话消息"** —— 还没定案。但调查的副产品是一个结论：**我们的系统提示词一行都不落盘**，"模型当时看到了什么"重建不出来。

### 三、踩的坑 / 改判

- **`toEqual` 陷阱**：`cachedInput` 必须"没有就不写键"，写 0 会让 `lib/deepseekModel` 那条 `toEqual` 断言当场变红，而且语义上把"不知道"说成"零命中"。
- **中止分支把 `acc.usage` 扔了**：原来写死 `usage: EMPTY_USAGE`，改成 `acc.usage ?? EMPTY_USAGE`。真 bug，不是重构。
- **aborted 那笔的 0 是占位**：累加时必须跳过它，否则它会以 0 参与"是否缺数"的判定。
- **演示文件我谎报过一次**：上一轮说"demo 已经做好了 `prototype-c68-cache-panel-v2.html`"，其实没有创建 —— 用户问"html 文件是哪个"才发现。以后说"文件已写入"必须先落盘再说。
